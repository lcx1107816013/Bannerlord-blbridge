# 开发文档

## 一、架构说明

系统由三段组成，整体走"本地文件桥接"，不在 MOD 端实现任何 MCP 协议：

1. **AI Agent（MCP 客户端）**：发起 tool call（如 `spawn_troop`）。
2. **Python MCP Server（本仓库 `mcp_server/`）**：监听 stdio，按 JSON-RPC 解析 MCP 协议；收到调用后把指令写进 `cmd.txt`，并轮询读取 `state.json` 作为返回。
3. **游戏内 Lua 桥（`lua_mod/bridge.lua`）**：在游戏 tick 中轮询 `cmd.txt`，解析后调用游戏 API，把结果写回 `state.json`。

设计取舍：把"协议解析"外移到 Python，使 MOD 端保持极薄（仅文件 IO + 游戏调用），降低 MOD 崩溃风险与维护成本。

## 二、通信协议（文件轮询指令格式）

所有通信通过两个文本文件完成，路径由两端的 `DIR` / `BL_BRIDGE_DIR` 共同决定，必须指向同一目录。

### 2.1 下发指令 `cmd.txt`

- 内容为**一行 JSON**，表示一个指令对象。
- 字段：
  - `op`：操作名（白名单，共 46 个，见第四节）。
  - `seq`：由 Python 端自增的序号，用于回执对齐。
  - `ts`：下发时间戳（秒）。
  - 其余字段为参数，如 `partyId`、`troopId`、`count`、`heroId`。
- 示例：`{"op":"spawn_troop","seq":7,"ts":1710000000.123,"partyId":"player","troopId":"empire_infantry5","count":20}`
- 写文件采用**原子写**（先写 `cmd.txt.tmp` 再 `os.replace`），杜绝半写。

### 2.2 状态回写 `state.json`

- 内容为**一行 JSON**，表示执行结果，**必须回写 `seq`**（与指令一致）。
- 成功：`{"seq":7,"ok":true,"partyId":"player","spawned":20}`。
- 失败：`{"seq":7,"err":"unknown_op"}` / `{"err":"bad_cmd","seq":-1}`。
- MOD 端每处理完一条新指令即覆盖写回。

### 2.3 时序

```
Agent --tool_call--> Python --写cmd.txt--> [磁盘]
                                      Lua tick 轮询读到 --> 执行游戏API --> 写state.json
Python <--读state.json-- [磁盘] <---------- 返回 Agent
```

- Python 写 `cmd.txt` 后进入轮询等待（最多 `BL_POLL_TIMEOUT` 秒，默认 10s），**仅接受 `seq` 与本次下发一致的回执**，从根本上规避旧回执/竞态误判；超时返回 `{"error":"timeout","seq":...}`。
- `cmd.txt` 同一时刻只承载**一条**待执行指令；新指令覆盖旧指令（队列机制见第三节）。

## 三、风险注意事项

### 3.1 禁止主线程 IO（最高优先级）

- 游戏主循环对卡顿极敏感，**任何 `cmd.txt` / `state.json` 的同步读写都不能放在主线程**。
- `lua_mod/bridge.lua` 的 `tick()` 必须由宿主环境在**独立协程 / 异步 tick / 低频定时器**中调用（典型间隔 0.5s），切勿在 `OnTick` 主路径里做阻塞文件操作。
- Python 端读取 `state.json` 的轮询也使用 `time.sleep` 让出，不占 CPU。

### 3.2 指令队列保护

- **去重**：MOD 端用 `last` 指纹记录已处理的指令字符串，相同内容不重复执行（避免 state.json 被反复覆盖）。
- **原子写**：`cmd.txt` 已由 Python 端"临时文件 + `os.replace`"整文件原子写，防止读到半截 JSON。
- **seq 对齐**：每条指令带自增 `seq`，Python 只接受 `seq` 匹配的回执，彻底避免拿到上一条指令的旧结果。
- **长度校验**：MOD 端对畸形/超长内容直接返回 `bad_cmd`，不解析。
- **批量编排**：单条指令为"覆盖式"；需要连续多条时用 `run_ops` 工具逐条下发并等待回执，或自行串行调用。

### 3.3 安全

- `cmd.txt` 内容经 Lua 受限环境加载（`load(...,"t",safeEnv)`），阻断 `os`/`io` 等危险全局，仅允许构造数据表；仍建议仅信任本地 Agent。
- 绝不把 token、存档、账号写入 `state.json` 或提交仓库（见 `.gitignore`）。
- MCP Server 仅做本地文件桥接，不要监听公网端口。

## 四、操作 op 清单（46 个）

**本地工具（11 个，Python 直接处理，不经过游戏）**：
`ping` `get_bridge_info` `list_ops` `get_protocol` `read_state` `wait_for_state` `clear_state` `assert_state` `run_ops` `send_raw` `sleep`

**游戏 op（46 个，写入 `cmd.txt` 交由 MOD 执行）**：

- 主角 / 英雄：`get_player` `set_player_gold` `add_player_gold` `get_player_inventory` `add_item` `get_hero_stats` `list_heroes` `set_hero_attr` `heal_hero` `wound_hero`
- 部队：`spawn_troop` `list_parties` `get_party` `add_troops` `remove_troops` `disband_party` `teleport_party` `merge_parties` `start_battle` `auto_resolve_battle` `get_visible_parties` `get_map_entities`
- 定居点：`list_settlements` `get_settlement` `set_settlement_owner`
- 王国 / 家族 / 外交：`list_kingdoms` `list_clans` `declare_war` `make_peace` `get_relations`
- 世界 / 时间：`get_campaign_time` `get_time_scale` `set_time_scale` `fast_forward` `pause_game` `resume_game` `get_weather` `set_weather`
- 任务 / 日志 / 存档：`list_quests` `add_quest` `complete_quest` `get_missions` `get_campaign_log` `save_game` `load_game`
- 测试辅助：`take_snapshot`

> 新增 op 时，需在 `mcp_server/server.py` 的 `ENTRIES` 与 `lua_mod/bridge.lua` 的 `OP2FN` 两处同步登记。
> 也可在运行时用 `list_ops` / `get_protocol` 工具自省当前工具集与协议。
