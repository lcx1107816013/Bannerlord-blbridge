# 工具链联动（Bannerlord MOD 自动化）

本项目即 **BlBridge**（骑砍2 战斗遥测 + AI 推演桥）。它是一个 mod 包，含**两个单元**与**两条接入通道**：

- **单元 A** = `Modules/BlBridge/`（`SubModule.xml` + `bin\...\BlBridge.dll`）：游戏与启动器读它，提供 C# DLL 后端。
- **单元 B** = `Modules/BlBridge/mcp/`（MCP 服务器 + `AI-TUTORIAL.md` + `manifest.json`）：AI 读它，把控制通道接成 MCP 工具。
- **本仓库**承载 BlBridge 的**文本通道**实现（`lua_mod/` Lua 桥 + `mcp_server/` Python MCP）。

> 注意：`blbridge` MCP **不是第三方**，它是本项目（BlBridge）自带的 MCP 子包。外部依赖只有 `bannerlordsage`（资料库）与 `bannerlordhelper`（汉化）。

## 一、BlBridge 的两条接入通道

两条通道**同源同项目**，都走**本地文件 IPC**（无 HTTP、无端口、无提权），可并存：

| | **DLL 通道**（单元 A + B） | **文本通道**（本仓库） |
|---|---|---|
| 实现 | C# `BlBridge.dll` + `bl_mcp.py` | `lua_mod/bridge.lua` + `mcp_server/server.py` |
| 通信 | `<文档>\Mount and Blade II Bannerlord\BlBridge\commands\{pending,done}` | `<MOD目录>\cmd.txt` / `state.json` |
| 能力 | 全：遥测(JSONL)、启动(BLSE)、UI 探测、存档直载、配置、战场改令/接管、相机 | 专注：自定义游戏内 op + 脚本化编排 + 断言 |
| 部署 | 编译 DLL 并部署（`build.ps1 -Deploy`） | 纯文本，放进 `Modules/` 即可 |
| 扩展 | 改 C#，需重编 | 加 op 只改 `ENTRIES` + `OP2FN` 两处 |
| 定位 | 「重活」与端到端控制 | 「轻活」与自定义脚本/回归测试 |

> 经验法则：**启动 / UI / 存档 / 配置 / 战场控制 → DLL 通道**；**自定义指令、批量编排、跨机编排、无编译快速实验 → 文本通道**。

## 二、外部 MCP 服务器（查 / 造 / 译）

| 服务器 | 角色 | 关键工具 |
|---|---|---|
| `bannerlordsage`（资料库） | 知识 / API / 脚手架 / 补丁 / 索引 | `search_bannerlord_knowledge`、`search_bannerlord_api_docs`、`bannerlord_doctor`、`create_mod_workspace`、`generate_harmony_patch`、`generate_xslt_patch`、`index_mod_source` |
| `bannerlordhelper`（汉化） | 本地化 / 汉化 / 外置汉化包 | `bh_list_local_modules`、`bh_list_languages`、`bh_translate_module`、`bh_create_external_translation`、`bh_search_nexusmods` |

## 三、能力清单

| 需求 | 归属 | 代表工具 |
|---|---|---|
| 启动游戏 / BLSE 调试 | **本项目·DLL 通道** | `bl_launch_game`（自动应答弹窗、跳过场动画）、`bl_status`、`bl_get_screen` |

## 四、端到端流水线

```
[1] 查资料        bannerlordsage.search_bannerlord_knowledge / search_bannerlord_api_docs
        │
[2] 造/改 MOD     bannerlordsage.create_mod_workspace + generate_harmony_patch / generate_xslt_patch
        │         bannerlordsage.index_mod_source
        │
[3] 汉化          bannerlordhelper.bh_list_local_modules → bh_translate_module
        │
[4] 打包          GitHub Actions（.github/workflows/package-mod.yml）→ MOD zip
        │
[5] 启动          BlBridge·DLL 通道：bl_launch_game（走 BLSE，自动应答模态弹窗、跳过场动画）
        │
[6] 进场景        bl_open_ui（默认 CustomBattle）→ bl_wait_for_state 等 activeState 就绪
        │
[7] 运行/调试     bl_status（源码/构建/部署/进程一致性）+ bl_get_screen（读界面按钮）
        │         BlBridge·文本通道：read_state / get_bridge_info / list_ops 做桥接自检
        │
[8] 自动化测试    BlBridge·文本通道：run_ops 批量下发 + assert_state 断言
        │         BlBridge·DLL 通道：bl_start_battle / bl_battle_status / bl_order 驱动战斗
        │
[9] 回归 / 迭代   重复 [2]→[8]；bannerlord_doctor 复核加载顺序
```

## 五、注意事项与边界

- **独立进程、由 Agent 编排**：BlBridge 的两条通道（`blbridge` MCP 子包 + 本仓库 `mcp_server`）与两个外部服务器（`bannerlordsage` / `bannerlordhelper`）都是独立 MCP 进程，彼此不直接通信，统一由 AI Agent 调度。
- **BLSE 依赖**：`bl_launch_game` 走 BLSE 且分两步（先等窗口、再等主菜单就绪）；本仓库 Lua 桥同样需要 BLSE/Lua 宿主。
- **版本敏感**：游戏 API 名随版本与 Lua 桥而变；用 `search_bannerlord_api_docs`（可指定 `version`）核对后再写绑定/补丁。
- **安全**：`bl_launch_game` / `bl_load_save` / `bl_apply_config` 会改变运行状态或磁盘文件，请在可回退环境使用；两条通道均不暴露网络端口。
- **唯一真相源**：`Modules\BlBridge\mcp\*.py` 是构建产物，真源在开发仓库 `tools\*.py`，`build.ps1 -Deploy` 会覆盖——别直接改游戏目录里的副本。

## 六、两条通道怎么选（同一项目内部）

| 场景 | 选通道 | 工具示例 |
|------|--------|----------|
| 启动游戏 / 进战斗 / 处理弹窗 | DLL 通道 | `bl_launch_game` |
| 读界面 / 点按钮（Gauntlet UI） | DLL 通道 | `bl_get_screen`、`bl_open_ui`、`bl_close_ui` |
| 存档读写、配置、相机、战场改令 | DLL 通道 | `bl_load_save`、`bl_apply_config`、`bl_order` |
| 自定义指令 / 批量编排 / 跨机 | 文本通道 | `run_ops`、`send_raw`、`BL_BRIDGE_DIR` 指向共享盘 |
| 自动化断言 / 回归 | 文本通道 | `assert_state`、`wait_for_state`、`take_snapshot` |
| 无游戏时联调协议 | 文本通道 | `ping`、`get_bridge_info`、`read_state` |

## 七、示例脚本

- `examples/e2e_pipeline.py` —— 内置极简 MCP stdio 客户端，把各服务器按流水线串一遍。
  - `--list`：只打印步骤（标注是否副作用）。
  - 默认 `--only-safe`：只跑无副作用步骤；未配置启动命令的服务器其步骤自动**跳过**（开箱即用）。
  - `--all`：执行全部步骤（会写文件 / 启动游戏，**慎用**）。
- `examples/servers.example.json` —— 各服务器启动命令模板，复制为 `servers.json` 填写后即可让本项目的 DLL 通道（`blbridge`）与外部 sage/helper 的步骤真正执行。
