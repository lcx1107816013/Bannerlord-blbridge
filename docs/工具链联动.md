# 工具链联动（Bannerlord MOD 自动化）

本项目的定位是「**轻量脚本化桥**」，自身不做全部事情。Bannerlord 的 **编辑 / 制作 / 调试 / 汉化 / 客户端与 BLSE 操控** 由现成的三个 MCP 服务器提供，AI Agent（MCP 客户端，如 CodeBuddy）作为**统一调度方**把它们串起来，形成端到端自动化流水线。

> 一句话：`bannerlordsage` 负责「**查与造**」，`bannerlordhelper` 负责「**译**」，`blbridge` 负责「**跑与控制**」，本项目负责「**脚本化编排与断言**」。

## 一、四个组件与分工

| 组件（MCP 服务器） | 角色 | 关键工具 |
|---|---|---|
| `bannerlordsage`（霸主资料库） | 资料 / 知识 / API / 脚手架 / 补丁生成 | `search_bannerlord_knowledge`、`search_bannerlord_api_docs`、`search_bannerlord_docs`、`bannerlord_doctor`、`create_mod_workspace`、`generate_harmony_patch`、`generate_xslt_patch`、`index_mod_source`、`search_mod_source`、`read_mod_type`、`get_entity` |
| `bannerlordhelper`（汉化工具） | 本地化 / 汉化 / 外置汉化包 | `bh_list_local_modules`、`bh_list_languages`、`bh_translate_module`、`bh_create_external_translation`、`bh_generate_template`、`bh_search_nexusmods`、`bh_run_cli` |
| `blbridge`（运行时 / 客户端） | 启动、客户端控制、运行时调试、战斗/相机/配置 | `bl_launch_game`、`bl_status`、`bl_get_screen`、`bl_list_ui`、`bl_open_ui`、`bl_close_ui`、`bl_load_save`、`bl_list_saves`、`bl_start_battle`、`bl_battle_status`、`bl_order`、`bl_control_agent`、`bl_apply_config`、`bl_apply_rts_config`、`bl_ghost_camera`、`bl_cheat_mode`、`bl_fast_forward`、`bl_wait_for_state` |
| **本项目 `Bannerlord-blbridge`** | 轻量 Lua 文本桥：把游戏内操作暴露成标准 MCP 工具，做脚本化编排与自动化测试 | 57 个工具（`spawn_troop`、`list_parties`、`set_player_gold`、`run_ops`、`assert_state` …），见 README「工具列表」 |

### `blbridge` 与本项目的区别

| | `blbridge` | 本项目 `Bannerlord-blbridge` |
|---|---|---|
| 接入方式 | C# DLL 直连游戏进程 | **Lua 文本文件桥**（`cmd.txt` / `state.json`） |
| 能力强度 | 强（界面探测、载档、战斗、相机、配置） | 轻（自定义 op，可自由扩展） |
| 部署成本 | 需编译部署 DLL，随版本更新 | 纯文本、可移植、几乎无编译 |
| 适用 | 端到端客户机控制与调试 | 快速自定义测试指令、跨机/共享目录编排 |

两者**互补**：用 `blbridge` 做「重活」（启动、进战斗、界面/存档/配置），用本项目做「自定义脚本化与断言」。

## 二、能力清单（对应你的问题）

| 需求 | 是否具备 | 由谁提供 |
|---|---|---|
| MOD **编辑 / 制作**（脚手架、C# 工程、Harmony/XSLT 补丁） | ✅ | `bannerlordsage`（`create_mod_workspace` / `generate_harmony_patch` / `generate_xslt_patch`） |
| MOD **源码索引 / 语义检索 / 反编译阅读** | ✅ | `bannerlordsage`（`index_mod_source` / `search_mod_source` / `read_mod_type`） |
| **资料库 / API 查询** | ✅ | `bannerlordsage`（`search_bannerlord_knowledge` / `search_bannerlord_api_docs`） |
| 安装/依赖/加载顺序**诊断** | ✅ | `bannerlordsage.bannerlord_doctor` |
| **汉化 / 本地化 / 外置汉化包** | ✅ | `bannerlordhelper`（`bh_translate_module` / `bh_create_external_translation`） |
| 游戏**启动 / 调用**（走 BLSE，无人值守进自定义战斗） | ✅ | `blbridge.bl_launch_game` |
| **BLSE / 客户端调试**（状态、构建一致性、界面探测） | ✅ | `blbridge.bl_status` / `bl_get_screen` / `bl_list_ui` |
| 存档 / 配置 / 相机 / 战斗控制 | ✅ | `blbridge`（`bl_load_save` / `bl_apply_config` / `bl_ghost_camera` / `bl_start_battle` …） |
| **脚本化编排 / 自动化断言测试** | ✅ | 本项目（`run_ops` / `assert_state` / `wait_for_state` + 46 个游戏 op） |

> 结论：你要的这些功能**都有**，且各由专门的 MCP 提供；本项目补上「轻量、可自定义、纯文本可移植」的一环。

## 三、端到端自动化流水线

```
[1] 查资料         bannerlordsage.search_bannerlord_knowledge / search_bannerlord_api_docs
        │
[2] 造/改 MOD      bannerlordsage.create_mod_workspace + generate_harmony_patch / generate_xslt_patch
        │          bannerlordsage.index_mod_source（建索引，便于语义检索与后续改动）
        │
[3] 汉化           bannerlordhelper.bh_list_local_modules → bh_translate_module（或 bh_create_external_translation）
        │
[4] 打包           GitHub Actions（.github/workflows/package-mod.yml）→ 产出 MOD zip
        │
[5] 启动           blbridge.bl_launch_game（走 BLSE；自动应答 Safe Mode / Mod change 弹窗，跳过场动画）
        │
[6] 进场景         blbridge.bl_open_ui（如 CustomBattle）→ bl_wait_for_state 等 activeState 就绪
        │
[7] 运行/调试      blbridge.bl_status（源码/构建/部署/进程一致性）+ bl_get_screen（读界面按钮）
        │          本项目：read_state / get_bridge_info / list_ops 做桥接自检
        │
[8] 自动化测试     本项目：run_ops 批量下发 + assert_state 断言；
        │          blbridge：bl_start_battle / bl_battle_status / bl_order 驱动战斗
        │
[9] 回归 / 迭代    重复 [2]→[8]；bannerlord_doctor 校验加载顺序
```

## 四、注意事项与边界

- **独立进程**：四个 MCP 各自运行，彼此不直接通信；**由 AI Agent 统一编排**（本项目自身就是一个 MCP，同样可被 Agent 调度）。
- **BLSE 依赖**：`bl_launch_game` 明确走 BLSE，并分两步（先等窗口、再等主菜单就绪）以避免启动期崩溃；本项目 Lua 桥同样需要 BLSE/Lua 宿主才能生效。
- **版本敏感**：游戏 API 名/属性随**游戏版本与 Lua 桥**而变；`bannerlordsage` 的 API 文档可按 `version` 匹配，`bindings.lua` 中的名字请在目标版本核对。
- **安全**：`bl_launch_game` / `bl_load_save` / `bl_apply_config` 等会**改变运行状态或磁盘文件**，请在可回退的环境中使用；本项目仅做本地文件桥，不暴露网络端口。
- **职责边界**：本项目不内置「查资料 / 汉化 / 客户端控制」逻辑，避免重复造轮子；需要这些能力时由 Agent 调用对应 MCP。

## 五、典型编排示例（伪代码）

```
# 1) 查 API 确认目标方法签名
bannerlordsage.search_bannerlord_api_docs(query="MobileParty")

# 2) 生成 Harmony 补丁脚手架并写入 MOD 源码
bannerlordsage.generate_harmony_patch(className="MobileParty", methodName="CalculateSpeed")

# 3) 重建源码索引
bannerlordsage.index_mod_source(workspaceRoot="<mod-src>")

# 4) 生成并写入中文汉化
bannerlordhelper.bh_translate_module(module="MyMod", to="CNs")

# 5) 启动游戏并进自定义战斗
blbridge.bl_launch_game(enterCustomBattle=True)

# 6) 用本项目做脚本化操作 + 断言
blbridge_blbridge.run_ops(ops=[
  {"name": "set_player_gold", "arguments": {"amount": 100000}},
  {"name": "spawn_troop", "arguments": {"partyId": "player", "troopId": "empire_infantry5", "count": 20}},
])
blbridge_blbridge.assert_state(key="ok", equals="True")
```

## 六、按场景选型对照：本项目 vs `blbridge`

两者都能操控游戏，但适用场景不同。**优先选「更贴近该场景的原生实现」**：

| 场景 | 推荐 | 代表工具 | 理由 |
|------|------|----------|------|
| 启动游戏 / 进战斗 | `blbridge` | `bl_launch_game` | 需 C# DLL 直连，且内置弹窗应答/跳过场动画 |
| 读界面 / 点按钮（Gauntlet UI） | `blbridge` | `bl_get_screen`、`bl_list_ui`、`bl_open_ui`、`bl_close_ui` | 能枚举界面层与按钮；文件桥做不到 |
| 存档读写 | `blbridge` | `bl_list_saves`、`bl_load_save` | 直连 `MBSaveLoad` |
| 配置 / 相机 / 作弊 | `blbridge` | `bl_apply_config`、`bl_apply_rts_config`、`bl_ghost_camera`、`bl_cheat_mode`、`bl_camera_speed` | 已有成熟实现 |
| 战场单位级控制 | `blbridge` | `bl_order`、`bl_control_agent`、`bl_battle_status` | 战场级能力 |
| 脚本化批量指令 / 自定义 op | **本项目** | `run_ops`、`send_raw` + `OP2FN` | 纯文本协议，加 op 只改两处，无需重编 DLL |
| 跨机 / 共享目录编排 | **本项目** | `BL_BRIDGE_DIR` 指向共享盘 | 文件桥天然支持远程目录 |
| 自动化断言 / 回归 | **本项目** | `assert_state`、`wait_for_state`、`take_snapshot` | 面向测试用例 |
| 无游戏时的协议联调 | **本项目** | `ping`、`get_bridge_info`、`read_state` | 桩实现即可端到端跑通 |
| MOD 制作 / 汉化 / 资料 | `bannerlordsage` / `bannerlordhelper` | 见第一节 | 各司其职 |

> 经验法则：**「重活」（启动、UI、存档、配置、战场）交给 `blbridge`；「自定义脚本、编排与断言」交给本项目**；「查/造/译」交给 sage/helper。

## 七、示例脚本

仓库内提供了**可运行的流水线 Demo**：

- `examples/e2e_pipeline.py` —— 内置一个极简 MCP stdio 客户端，把四个服务器按顺序串一遍。
  - `python examples/e2e_pipeline.py --list`：只打印流水线步骤（含每步是否为副作用）。
  - `python examples/e2e_pipeline.py`：默认 `--only-safe`，只跑无副作用步骤；未配置启动命令的服务器其步骤会被**跳过**（开箱即用，仅本项目会被真正拉起）。
  - `python examples/e2e_pipeline.py --all`：执行全部步骤（会写文件 / 启动游戏，**慎用**）。
- `examples/servers.example.json` —— 服务器启动命令配置模板，复制为 `servers.json` 填写即可让 sage/helper/blbridge 的步骤真正执行。
